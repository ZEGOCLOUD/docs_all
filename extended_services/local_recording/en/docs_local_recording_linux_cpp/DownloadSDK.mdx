<Accordion title="2021-12-02 Version: gd2ef35d43f">

**New features**

1. Adapted to the overall H.265 solution
    
    The complete H.265 encoding/decoding solution is now available, applicable to single-host live streaming and multi-host interactive live streaming scenarios. This plugin mainly adapts to the H.265 automatic fallback (H.265 falling back to H.264) capability of the RTC product, and two files (one H.265 file and one H.264 file) are generated during recording.

2. Supports taking screenshots of specified streams.
3. Supports capturing audio input sources during external capture.
4. During mixed-stream recording, the following features are added:

    - Supports setting image watermarks.
    - Supports pausing/resuming recording during mixed-stream recording.
    - Supports setting a background image for specified streams during mixed-stream recording.

**Deprecations**

To make environment configuration easier for developers, the test environment has been deprecated, and the production environment is used uniformly. In versions `gd2ef35d43f` and above, the original [SetUseTestEnv] API for setting whether to use the test environment is deprecated. Developers no longer need to set environment information and can use it directly.

</Accordion>

<Accordion title="2020-12-09 Version: g5dbbce505a">

**New features**

1. Recording supports the m3u8 file format.

2. Supports setting the layout mode (cropping or black bars).

3. The stream update callback adds the stream creation time information.

4. Supports setting the bitrate for externally input video data.

5. Supports using externally input video data as the recording input source.

**Improvements**

1. Corrected the video timestamps of mixed-stream recording, making them more uniform and aligned with the frame rate.

2. Mixed-stream recording supports recording more streams, fixing the previous bottleneck issue.

3. Optimized MP3 format recording so that silent data can be padded.

4. Optimized the issue where domain name resolution might take too long.

**Bug fixes**

1. Fixed the issue where the recorded file had no sound after the audio format of the input stream was switched during single-stream recording.

2. Increased the data cache, fixing the issue where the process could get stuck when system I/O took a long time.

3. Fixed the issue where OnRecordEnd might be triggered multiple times.

4. Fixed the issue where no recording failure callback was triggered when single-stream recording exceeded the upper limit.

5. Fixed the crash issue caused by duplicate input stream IDs during mixed-stream recording.

6. Fixed the issue where the room could not be exited.

</Accordion>

<Accordion title="2020-04-30 Version: g709410abf">
 
**New features**

1. Login authentication  
Added the [SetToken](https://doc-en.zego.im/API/ServerRecord-en/html/namespace_z_e_g_o_1_1_l_i_v_e_r_o_o_m.html#aa0b8eca203fb7b2f40b69f1c853d29f4) API for setting custom authentication information to verify the legitimacy of the user upon login. 
2. Setting user information  
Added the [SetUser](https://doc-en.zego.im/API/ServerRecord-en/html/namespace_z_e_g_o_1_1_l_i_v_e_r_o_o_m.html#a7ac98e20f63c4fae7266214be860a089) API for setting the username and related information.  
3. Obtaining the absolute timestamp when recording starts  
In online education scenarios, the teacher may publish the live stream while editing the whiteboard at the same time. You can use the ZEGO recording SDK to record the teacher's live audio/video stream and obtain the absolute timestamp relative to the teacher's client when recording starts, which is used to align the teacher's audio/video recording files with the whiteboard data.   
(1) Added the [onRecvMediaSideInfo](https://doc-en.zego.im/API/ServerRecord-en/html/class_z_e_g_o_1_1_l_i_v_e_r_o_o_m_1_1_i_media_side_callback.html#a1ebd6831721ce03e71db1c52a904e008) callback, through which the media side information sent by the publishing client can be received.  
(2) Added the [GetRecordLastMediaSideTime](https://doc-en.zego.im/API/ServerRecord-en/html/namespace_z_e_g_o_1_1_l_i_v_e_r_o_o_m.html#af11acf7b7af97126a6cbe2fca2e7cca9) API to get the time interval between the most recently received media side information packet and the first recorded packet.  

  After the publishing client starts publishing, it periodically sends media side information (with the current absolute timestamp filled in). After the recording client receives it, the parsed timestamp minus the time returned by `GetRecordLastMediaSideTime` is the absolute timestamp when recording starts. 

4. Obtaining information about recording files  
Added the [GetRecordStatus](https://doc-en.zego.im/API/ServerRecord-en/html/namespace_z_e_g_o_1_1_l_i_v_e_r_o_o_m.html#a1c2d983f3d3cef1ef0b54288e9e2eac3) API for getting the storage path, recorded duration, and file size of the recording file.  
5. Added the ability to set watermark attributes such as position, font color, and background color.

**Bug fixes**

1. Fixed the bug where no error callback was triggered when pulling the flexible configuration failed.
2. Fixed the bug where the [LoginRoom](https://doc-en.zego.im/API/ServerRecord-en/html/namespace_z_e_g_o_1_1_l_i_v_e_r_o_o_m.html#ac13869a794f456b739a5c9240e8f752c) callback returned success when the [InitSDK](https://doc-en.zego.im/API/ServerRecord-en/html/namespace_z_e_g_o_1_1_l_i_v_e_r_o_o_m.html#a0b05e2d88f37fe107e55c6f01809674b) call failed.
3. When a stream is removed from the mixed-stream input, the [OnMixStreamRecordUpdate](https://doc-en.zego.im/API/ServerRecord-en/html/class_z_e_g_o_1_1_l_i_v_e_r_o_o_m_1_1_i_callback.html#ad5838ef43c3ec75de7f556c085fba7f3) callback is triggered.
</Accordion>
