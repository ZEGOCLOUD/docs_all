# Channel conversation management

- - -

## Overview

Each Community channel corresponds to a conversation of type `COMMUNITY_CHANNEL`. Using the channel's `conversationID`, you can operate on channel conversations through ZIM's standard conversation management APIs, including:

- Getting the channel list (including the conversation ID)
- Clearing the unread message count of a channel
- Setting/clearing the draft of a channel conversation
- Configuring Do Not Disturb for a channel conversation
- Listening for channel conversation changes
- Syncing channel conversations to the conversation list

## Prerequisites

- Please refer to [Send and receive messages](../Messaging/Send%20and%20receive%20messages.mdx) to complete ZIM SDK integration, initialization, and user login.
- Please refer to [Token-based authentication](../Users/Authentication.mdx) to implement user authentication login.
- The Community feature requires ZIM SDK 3.0.0 or later.
- The Community feature is part of the Premium plan. Please contact ZEGOCLOUD Technical Support to enable it before use.
- The Token generation for the Community feature is consistent with other ZIM features, and no additional permission declarations are required.

<Note title="Note">
- The `conversationID` of a channel conversation is different from the channel's `channelID`. When sending messages and managing conversations, please use the `conversationID` field obtained from the {getPlatformData(props,ZIMCommunityChannelMap)} object.
</Note>

<Warning title="Warning">
Do not mistakenly use `channelID` as `conversationID`. When sending messages and performing conversation management operations, you must use the `conversationID` obtained from the channel object (`ZIMCommunityChannel`), not `channelID`.
</Warning>

## Get the channel list

Before managing channel conversations, you need to call the {getPlatformData(props,queryCommunityChannelListMap)} API to get the channel list and obtain the `conversationID` from the returned `ZIMCommunityChannel` object for subsequent conversation operations.

Pagination rule: Set `config.nextFlag` to `0` for the first request, pass the returned `nextFlag` to the next request, and continue until `0` is returned.

:::if{props.platform=undefined}
<CodeGroup>
```java title="Example code"
import im.zego.zim.ZIM;
import im.zego.zim.callback.ZIMCommunityChannelListQueriedCallback;
import im.zego.zim.entity.ZIMCommunityChannel;
import im.zego.zim.entity.ZIMCommunityChannelListQueryConfig;
import im.zego.zim.entity.ZIMError;
import im.zego.zim.enums.ZIMErrorCode;

ZIMCommunityChannelListQueryConfig config = new ZIMCommunityChannelListQueryConfig();
config.setNextFlag(0);

zim.queryCommunityChannelList(communityID, 100, config,
    new ZIMCommunityChannelListQueriedCallback() {
        @Override
        public void onCommunityChannelListQueried(String communityID, ArrayList<ZIMCommunityChannel> channelList, long nextFlag, ZIMError errorInfo) {
            if (errorInfo.code == ZIMErrorCode.SUCCESS) {
                for (ZIMCommunityChannel channel : channelList) {
                    String conversationID = channel.getConversationID(); // Used for subsequent conversation management
                }
            }
        }
    });
```
</CodeGroup>
:::
:::if{props.platform="iOS|mac"}
<CodeGroup>

## Clear unread message count

Call the {getPlatformData(props,clearConversationUnreadMessageCountMap)} API to reset the unread message count of a specified channel conversation to zero. After successful clearing, the {getPlatformData(props,onConversationChangedMap)} callback will be triggered to reflect the latest conversation state.

:::if{props.platform=undefined}
<CodeGroup>
```java title="Example code"

ZIMConversationType conversationType = ZIMConversationType.COMMUNITY_CHANNEL;

zim.clearConversationUnreadMessageCount(conversationID, conversationType,
    new ZIMConversationUnreadMessageCountClearedCallback() {
        @Override
        public void onConversationUnreadMessageCountCleared(String conversationID, ZIMConversationType conversationType, ZIMError errorInfo) {
            if (errorInfo.code == ZIMErrorCode.SUCCESS) {
                // Unread count cleared
            }

    });
```

```java title="Example code"
            if (errorInfo.code == ZIMErrorCode.SUCCESS) {
```

## Sync channel conversations to the conversation list

After this feature is enabled, community channel conversations are included in the ZIM conversation list together with one-on-one and group conversations: you can pull the complete list including channel conversations in one go through {getPlatformData(props,queryConversationListMap)}, and stay aware of changes to channel conversations such as the latest messages, unread counts, and drafts through {getPlatformData(props,onConversationChangedMap)}, without maintaining a separate list for community channels.

For channel conversations synced to the conversation list, the conversation type is `COMMUNITY_CHANNEL`, and the `conversationID` is still the `conversationID` field in the channel object {getPlatformData(props,ZIMCommunityChannelMap)}.

<Warning title="Warning">
- This feature is disabled by default. Contact ZEGOCLOUD Technical Support for activation before use. If it is not enabled, channel conversations do not appear in the conversation list, and no conversation change notifications of the `COMMUNITY_CHANNEL` type are generated.
- The current version only supports syncing the **default channel** of a Community to the conversation list. For other channels, continue to use {getPlatformData(props,queryCommunityChannelListMap)} to get and manage them.
</Warning>

### Supported conversation management capabilities

After channel conversations enter the conversation list, the available conversation management APIs are the same as the capabilities described earlier in this article:

| Conversation management capability | API | Supported |
| --- | --- | --- |
| Clear conversation unread count | {getPlatformData(props,clearConversationUnreadMessageCountMap)} | Yes |
| Set conversation draft | {getPlatformData(props,setConversationDraftMap)} | Yes |
| Set conversation Do Not Disturb | {getPlatformData(props,setConversationNotificationStatusMap)} | Yes |
| Pin conversation | {getPlatformData(props,updateConversationPinnedStateMap)} | Not supported yet |
| Mark conversation | {getPlatformData(props,setConversationMarkMap)} | Not supported yet |

### Get the community ID of a channel conversation

`ZIMConversation` adds a `relatedID` property to identify the ID of the object associated with the conversation. When the conversation type is `COMMUNITY_CHANNEL`, this value is the `communityID` of the Community that the channel belongs to.

In the conversation list scenario, you can directly locate the Community that a channel conversation belongs to through `relatedID`, for scenarios such as querying community public information and pulling the community member list, without maintaining the mapping between `conversationID` and `communityID` yourself.

<Note title="Note">

In the current version, the meaning of `relatedID` is clearly defined only when the conversation type is `COMMUNITY_CHANNEL`.
</Note>

### Listen for community channel conversation updates

The addition, update, and deletion of channel conversations are notified through the {getPlatformData(props,onConversationChangedMap)} callback, just like one-on-one and group conversations. In the callback, you can filter out conversations of the `COMMUNITY_CHANNEL` type and update the display of community channels in the conversation list.

:::if{props.platform=undefined}
<CodeGroup>
```java title="Example code"
// Register SDK event notification callbacks
zim.setEventHandler(new ZIMEventHandler() {
    @Override
    public void onConversationChanged(ZIM zim, ArrayList<ZIMConversationChangeInfo> conversationChangeInfoList) {
        for (ZIMConversationChangeInfo changeInfo : conversationChangeInfoList) {
            ZIMConversation conversation = changeInfo.conversation;
            if (conversation.type != ZIMConversationType.COMMUNITY_CHANNEL) {
                // Not a channel conversation, handle it with the original logic
                continue;
            }
            // changeInfo.action: ADDED (conversation added), UPDATED (conversation updated), DELETED (conversation deleted)
            String conversationID = conversation.conversationID;    // Channel conversation ID
            String communityID = conversation.relatedID;            // ID of the Community that the channel conversation belongs to
            int unreadMessageCount = conversation.unreadMessageCount;
            String draft = conversation.draft;
        }
    }
});
```
</CodeGroup>

## Listen for channel list changes

When channels in a Community are created, disbanded, or their visible information changes, the channel list updates accordingly. The SDK notifies the developer through the `onCommunityChannelListChanged` callback. You can re-fetch the channel list in this callback to update the local `conversationID` mapping. For details, see [Community channel management - Listen for channel list changes](./channel-management.mdx#listen-for-channel-list-changes).

<Note title="Note">

Changes to channel conversations (such as unread count changes, draft updates, etc.) will also trigger the {getPlatformData(props,onConversationChangedMap)} callback. For the complete usage of conversation change listening, refer to [Get the conversation list](../Conversation/Get%20the%20conversation%20list.mdx).
</Note>
